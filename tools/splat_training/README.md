# Обучение сплатов на Python

Прототип запускается из корня репозитория и читает сохранённый приложением `.pscan`. SlangPy компилирует исходники из [каталога шейдеров Android](../../android/app/src/main/cpp/vk/shaders) при старте. Python связывает буферы по именам, заменяя в памяти объявления Vulkan-привязок и push constants. Проекция, GPU scan и radix sort, растеризация, обратные проходы, SSIM, лосс глубины, билатеральная сетка и Adam используют те же шейдеры, что и приложение.

## Запуск

Python 3.10+, GPU с Metal или Vulkan. На macOS нужен Xcode с установленным Metal Toolchain. По умолчанию выбирается Metal на macOS и Vulkan на остальных системах. Подробности установки есть в [документации SlangPy](https://slangpy.shader-slang.org/en/stable/).

```bash
python3 -m venv tools/splat_training/.venv
source tools/splat_training/.venv/bin/activate
python -m pip install -r tools/splat_training/requirements.txt
python -m pip install tensorboard  # Для --tensorboard

python -m tools.splat_training "$HOME/Downloads/scan-20261122-171427.pscan" \
  --output /tmp/pocket-splat-debug --epochs 2 --max-frames 12 \
  --validation-every 1 --tensorboard
```

`--max-frames` берёт первые N кадров по ID после фильтрации по размеру. Уберите его для полного набора. По умолчанию обучение идёт 100 эпох с бюджетом 3 млн гауссиан. Для validation выделяется 5% кадров, проход выполняется каждые 5 эпох. Для нового запуска укажите новый каталог `--output`. Если в архиве нет `mesh.ply`, передайте бинарный PLY, экспортированный из приложения, через `--mesh`.

Посев использует размер вокселя из `comment voxel` в PLY. Кадры декодируются по одному, а Z16 переводится в метры по `depthScale` из манифеста. Validation обновляет только сетку своего кадра и измеряет цвет после обновления. Train измеряет цвет до обновления гауссиан и сетки.

## Отсев кадров

Отсев включён по умолчанию. Для прогона на всех train-кадрах добавьте `--no-filter-redundant-frames`. Набор validation выбирается перед отсевом, затем расписания Adam рассчитываются по оставшимся кадрам.

Тренер проецирует вершины и центры треугольников меша в train-кадры и сверяет их с Z16. Кадры с худшим совпадением глубины и меньшей резкостью рассматриваются первыми. После отсева остаются хотя бы 99% покрытых точек и 95% точек с измеренным параллаксом. Для параллакса нужны два наблюдения с базой от 5 см и углом между лучами от 3°. В каждом кубе со стороной пять вокселей остаются хотя бы 92% покрытия и 75% параллакса. Допустимая потеря округляется вниз до целого числа точек.

Для каждой исходной позы с подтверждённой глубиной остаётся train-кадр в пределах 35 см и 18° полного поворота. Кадры без подтверждённых точек остаются в обучении. В `run.json` сохраняются исходное количество train-кадров, ID исключённых кадров и кадров без подтверждений, покрытие и параллакс до и после отсева.

## Результаты и отладка

- `metrics.jsonl` — L1, SSIM, PSNR, inverse-depth L1, число гауссиан, счётчики шагов, разрешение и время каждого прохода. В validation поля `raw_l1`, `raw_ssim` и `raw_psnr` измеряются до коррекции цвета билатеральной сеткой. `depth_mae_m` и `depth_rmse_m` считаются в метрах по пикселям, где есть и измерение, и предсказание. `depth_coverage` показывает долю таких пикселей среди всех валидных измерений.
- `run.json` и `hyperparameters.json` — ID кадров, настройки и горизонты расписаний.
- `val/<id>.png` — рендер с обновлённой сеткой текущего кадра validation.
- `scene.ply` — итоговые гауссианы в формате экспорта Android.
- `tensorboard/` — при `--tensorboard` содержит метрики по кадрам и эпохам, скорости обучения и количество пересечений с тайлами.

```bash
tensorboard --logdir /tmp/pocket-splat-debug/tensorboard
python -m unittest tools.splat_training.test_training
```

Для экспериментов передайте `--hyper settings.json` с нужными полями из [SplatHyper](../../android/app/src/main/cpp/vk/splat_train.h), например `{"densifyFrom": 5, "densifyInterval": 5, "gradThreshold": 0.0002}`. При стандартных настройках первое изменение плотности происходит на 500-м train-шаге. Для пошаговой отладки начните с `Trainer.step` в [trainer.py](trainer.py). Посев, clone/split/prune и сброс непрозрачности находятся в [population.py](population.py), управление GPU-буферами и сортировка — в [gpu.py](gpu.py).

Для сравнения фильтра и гиперпараметров при равном числе обновлений используйте одинаковые `--epochs`, `--steps-per-epoch` и `--validation-every`. Можно задать `--shuffle-seed 42`, чтобы детерминированно перемешивать train-кадры перед каждым обходом. Между эпохами обход продолжается с прежнего места. Например, `--epochs 3 --steps-per-epoch 128 --validation-every 1 --shuffle-seed 42` выполняет 384 шага Adam и оценивает модель после каждого блока из 128 шагов.

[Профиль короткого прогона](short-run.json) увеличивает начальный радиус гауссиан и проверяет уплотнение на шагах 128, 192, 256 и 320. Повышенный порог градиента ограничивает рост числа гауссиан.

```bash
python -m tools.splat_training "$HOME/Downloads/scan-20261122-171427.pscan" \
  --output /tmp/pocket-splat-short --hyper tools/splat_training/short-run.json \
  --epochs 3 --steps-per-epoch 128 --validation-every 1 --shuffle-seed 42
```

На этом архиве отсев оставил 189 из 406 train-кадров. После 384 шагов на 22 одинаковых validation-кадрах средний PSNR до цветовой коррекции составил 17,61 дБ без отсева, 17,42 дБ с отсевом и стандартными гиперпараметрами и 18,55 дБ с отсевом и коротким профилем. Значения inverse-depth L1 для тех же запусков составили 0,0666, 0,0690 и 0,0703 соответственно.

## Длинный прогон

[Профиль длинного прогона](long-run.json) использует более сильную привязку к глубине, снижает скорость обновления цвета до 25% к последнему шагу и обучает цвет напрямую при `lrGrid=0`. `--coarse-epochs` уменьшает разрешение первых эпох вдвое. При переходе на исходное разрешение сохраняются гауссианы, моменты Adam и расписания. Каждый validation-проход использует исходное разрешение. `--save-validation-scenes` сохраняет отдельный PLY для каждого измерения.

```bash
python -m tools.splat_training "$HOME/Downloads/scan-20261122-171427.pscan" \
  --output /tmp/pocket-splat-long-filtered --hyper tools/splat_training/long-run.json \
  --epochs 24 --steps-per-epoch 256 --coarse-epochs 18 --validation-every 2 \
  --shuffle-seed 42 --budget 100000 --save-validation-scenes
```

Для контрольного прогона укажите другой `--output` и добавьте `--no-filter-redundant-frames`. На одном GPU выполняйте прогоны последовательно. Сравнивайте строки с одинаковым `gauss_step` и сверяйте ID validation-кадров в `run.json`.

На этом архиве после 6 144 шагов PSNR до цветокоррекции составил 23,34 дБ с отсевом и 24,02 дБ без отсева. MAE глубины составила 7,56 и 7,12 см, RMSE в обоих случаях округлилась до 22,27 см. После сбоя Metal обе ветки продолжились с сохранённых моделей на шаге 3 584. Adam был одинаково переинициализирован в обеих ветках, оставшиеся скорости обучения сохранили исходное расписание.

Пара `--filter-pose-distance 0.12 --filter-pose-angle 8` требует более близкого представителя для каждой исходной позы, чем стандартные пороги 0,35 м и 18°. На том же скане она оставила 222 кадра вместо 189. В отдельном сравнении после 768 шагов дообучения в исходном разрешении от одной сохранённой модели PSNR вырос с 21,48 до 21,81 дБ, а MAE глубины снизилась с 7,72 до 7,64 см.

Ещё 768 шагов на 222 кадрах после основного прогона повысили PSNR с 23,34 до 23,93 дБ. Для этого этапа сохранились моменты Adam, использовались исходное разрешение и конечные скорости обновления цвета и центров гауссиан.
